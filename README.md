# 僵毁陪玩 · coopani-world-pz

让桌宠坐在旁边，陪你玩《僵尸毁灭工程》。

她读的是**游戏自己写出来的状态**，不是屏幕。所以她说得出「你 62% 血、八只僵尸、手上那把斧头剩 3 成耐久、背包里没有绷带」——而不是「注意安全哦」。

## 她看得到什么

游戏自己在写、我们只是转手：

| 类 | 内容 |
|---|---|
| 时间 | 第几天、几点、是不是夜里 |
| 位置 | 在室内还是外面、哪个房间、哪栋楼 |
| 身体 | 血量、感染状态与感染值、饥饿、口渴、疲劳、耐力 |
| 心情 | 疼痛、惊恐、压力、不高兴、无聊 |
| 威胁 | **视野里**有多少只僵尸（房子后面那一堆不算） |
| 装备 | 手上拿的什么、耐久多少 |
| 背包 | 绷带 / 食物 / 水 / 光源，各几样 |
| 手边 | **他正打开的那个容器**里有什么值得拿的（只看这一个），以及它在哪一格。**读过的书、等级已超过的技能书不会出现**（用游戏自己的 `isLiteratureRead` 判，不是猜书名） |
| 坐标 | 他自己站在哪（`x` / `y`）—— 她要走路就靠这个 |
| 事件 | 掉血多少、被咬感染、入夜、连杀、死亡 |
| 日程 | 前期电视上的技能课时间表（Life and Living TV） |

**看不到**：屏幕画面、你的准星、身上的地图、下一间屋里有什么、你刚弄出多大声响。

## 她什么时候开口

天要黑了还在外面 · 视野里的僵尸跨了一档（3 / 6 / 12）· 掉血 · 被感染 · 入夜 · 死亡。

还有两类不一样的东西：

- **他自己的状态**（`pz.need`）—— 饿了、渴了、累到底、体力空了、疼、慌、烦、闷。这类不是危险通知，是「我看见你现在什么样」。只会报场面的陪玩是在看地图，会说你这个人的才是在旁边坐着。
- **武器耐久见底**（`pz.weapon`）—— 20% 说一次、5% 再急一次。同一把武器同一档只说一遍，换刀不报（换刀这件事本身不需要她说），修好了再磨下去还能再说。
- **翻到好东西**（`pz.loot`）—— 他打开一个柜子，里面有大锤、发电机、能打的武器、工具、背包、光源或车钥匙，她提一句「别顺手划过去」。

- **前期电视课**（`pz.tv`）—— Life and Living TV 每天播技能课（烹饪/木工/钓鱼/农业/采集/陷阱），坐下来看就白涨经验，**一停电就没了**。快开播或刚开播时提一次，一天最多一次，第 5 天之后不再提。节目表是从游戏自己的 `media/radio/RadioData.xml` 抄的。

`pz.loot` 的边界是要写清楚的，不然它就是外挂：**只读他亲手打开的那一个容器**（游戏界面里的「正在翻的柜子」），不预告没去过的房间、不扫地图、不告诉他哪里有好东西。同一个柜子五分钟内只说一次。绷带、吃的、水**不在这条里**——`pz_tips` 已经在管，翻个柜子就念一遍会盖掉真正值钱的那句。觉得太像替你搜刮，设置里可以整个关掉。

每条都是**事实通知**，不是命令。怎么反应由她的口吻决定 —— 设置里四档：

- **毒舌队友**（默认）—— 看你犯蠢直接说，真到要命的地方收起来
- **稳当搭档** —— 话少，只在真该说的时候开口
- **慌里慌张的学妹** —— 她比你还紧张，紧张感本身就是提醒
- **按局面切换** —— 平时损你，血线掉下来立刻收

换的是**措辞和先想哪件事**，换不掉「该提醒的必须提醒」。

## 操作类功能还在内部验证

0.6.0 起试过「自己动手玩」——用游戏自己的动作系统走过去、拿东西、打僵尸。
那条链路现在还在验（寻路、反射、指令队列都有问题），**这一版默认只陪聊，设置页不提供开关**（实验性自主操作仅支持高级用户手动编辑配置 `worlds.pz.allowPlay: true` 开启）。

默认只做一件事：把看见的、值得说的说出来。不动你的手、不动你的鼠标。


## 怎么装

1. 装上这个扩展（市场或 `link:`），在设置里把「僵毁陪玩」打开。
2. **进一次游戏。** 到主菜单就够 —— 存档目录是那时才生成的。
3. 主菜单 → **Mods** → 勾上 **Coopani Bridge** → 读档。
4. 回来看看面板上「游戏」那盏灯是不是绿的。

第 2、3 步只需要一次。扩展会自己把桥接 mod 放进 `Zomboid/mods/CoopaniBridge`，不用手动拷。

> **为什么必须手动启用一次 mod。** 《僵尸毁灭工程》的 mod 列表默认是关着的，任何 mod 都一样。我们不去改游戏的 mod 激活配置 —— 那会把你自己勾好的清单一起覆盖掉。

## 她会不会被抬到你游戏画面上面

有一个开关「游戏运行时把她抬到最上层」，**默认关**。

打开后，扩展在游戏运行期间**每 5 秒**借宿主自带的 koffi 调一次
`SetWindowPos(hwnd, HWND_TOPMOST, …)`，把桌宠窗口重新置顶。它不抢焦点、不改位置，
只是为了应付「PZ 进世界重建窗口时把桌宠压到画面底下」这一种情况。

**为什么默认关。** 这是持续改写别的窗口的层级：独占全屏、录屏、带反作弊的软件都可能有意见；
而且它每 5 秒动一次别人的窗口，属于「影响范围大、但用户看不见」的那类行为 ——
开着的人得是自己知道的，不能靠默认值替他决定。

真要开，先在设置里打开这一项。想要又要不到，先看下面「找不到数据的时候」那条：
独占全屏本来就没法把窗口画上去，置顶也救不了。

## 数据通道

```
Lua 桥接 mod  ──每 2 秒覆盖写──▶  Zomboid/Lua/coopani-pz-state.json  ──▶  扩展轮询
```

只有一个文件、一种失败方式，诊断和说人话都简单。

**为什么不用 console.txt**：那是给自己看的调试输出，格式随版本变、单行还可能被截断。让游戏侧直接写结构化数据，比回头猜文本便宜一个量级。

**为什么状态和事件塞进同一个文件**：PZ 的 `getFileWriter` 是追加还是截断在版本间并不一致。追加的话文件会越长越长，症状是「她越玩越不准」——没人会往这上面想。现在的读法是覆盖写 + 解析失败时取最后一个完整对象，两种情况都活。

## 找不到数据的时候

她读了三个文件来分辨（`console.txt` / `Saves` / `mods/default.txt`），所以给的是**下一步点哪儿**：

| 现象 | 说明 | 怎么办 |
|---|---|---|
| 「游戏」灯灰 | 游戏没在跑 —— 正常状态，不是故障 | 想玩就开 |
| 「游戏」灯红 + 「游戏没在跑」 | 同上，但她在等你 | 开游戏 |
| 「游戏」灯红 + 「模组列表里没有」 | 文件放好了，但没在启用列表里 | 扩展会自动补写；**完全退出游戏重开一次** |
| 「桥接」灯绿但仍没数据 | mod 只在游戏启动时加载 | 完全退出游戏重开，别只回主菜单 |
| 她浮不到游戏画面上 | **独占全屏或无边框满屏**都会让 Windows 绕开桌面合成，置顶窗口物理上画不上去 | 选项 → 视频 → **「全屏」和「无边框」两个勾都取消**，用带标题栏的窗口模式（只关无边框会变成独占全屏）。重新置顶对这种情形无效 |
| 「游戏」灯红 + 「还没有任何存档」 | 这台机器上没建过角色 | **新游戏**建一个（不是「继续」） |
| 「游戏」灯红 + 「还没读档进世界」 | 在主菜单 | 点进那个档 |
| 「游戏」灯红 + 「加载时报错了」 | 桥接脚本在游戏里炸了 | 把我的锅 —— 把 console.txt 里提到 CoopaniBridge 的行发出来 |
| 「桥接」灯红 | 写不进 `Zomboid/mods` | 用管理员身份开一次 Coopani |

**每次重开游戏，这条提醒会重新武装一次。** 上一次没看见不会导致她永远闭嘴。

## 已知限制

- **只有 Windows**。路径和 `os.time()` 的假设都是 Windows 的。
- **只在 B42 上验过路径假设**（`media/lua/client` 这种旧式 mod 结构 B41 也认）。
- **没在真存档上跑过** —— 这台机器上游戏一次都没启动过。第一次进游戏也是第一次真机验证；如果数据没到，她会说清缺哪一步，不会闷着。
- 视野里的僵尸数只是视野内的，不代表附近只有这些。
- 感染值只是游戏给的那个数，它不等于「还剩几天」。

## 给开发者的几条

- **⚠️ Lua 里绝对不能把中文写进字符串字面量。** Kahlua 的词法器把非 ASCII 字符截成单字节，中文就变成乱码，还会夹 `0x1F` / `0x08` 这类控制字节。真机翻车：一条「过期了（这条是 352 秒前下的）」把整份 state 变成**非法 JSON**，外面报「读到半截 JSON」，而数据一个字段都没少。**做法：Lua 只发 ASCII 码**（`no-square` / `expired:352`），翻译放在 TS；`q()` 里再把 0x00–0x1F 一律转成 `\u00XX` 兜住；解析侧最后再去掉裸控制字符重试一次。注释里随便写中文，词法器会跳过注释。
- **⚠️ `ISTimedActionQueue` 的 `queue` 是 Lua 表，不是 Java List。** `o.queue = {}`，数它用 `#self.queue`，没有 `isEmpty()` 也没有 `size()`。按「Java 集合」的想法去调，就是每 120 帧一整段堆栈。
- **⚠️ Lua 的 `local` 不是文件级的，是「声明点之后」。** 函数用到的表，声明必须在函数**前面**，否则函数里那个名字悄悄变成**全局 nil** —— 语法合法、静态检查看不出、运行时每拍抛 `attempted index: xxx of non-table: null`。真机翻车：`local ENUM_RANGE` 在 301 行、`normNeed` 在 262 行，结果所有属性读数是 `null`，外加每拍一整段堆栈。**判据：凡「表 / 常量」被函数用，声明一律放在文件靠前的集中区。**
- **⚠️ 「包了 pcall」不等于「没打日志」。** `pcall` 接得住异常，接不住 Kahlua 的堆栈打印 —— 每接一次照样打一整段。高频路径（每帧 / 每 120 帧）里，**先保证不抛**，别指望 pcall 兜。`q.queue:isEmpty()` 在 B42 上不存在，每 120 帧刷一次堆栈就是这么来的。
- **⚠️ 跨进程数据里，`undefined`（键不存在）和 `null`（键在、值是空）是两件事。** `x !== null` 只挡得住后者。真机翻车：游戏刚启动时 state 里**没有 `gear` 这个键**，`gear !== null` 为真 → 读 `.water` 抛 → `start()` 的第一句就是 `tick()` → 宿主报「**切换失败**」，整个扩展开不起来。**判据：凡是来自 state 文件 / 配置 / 外部接口的值，一律用 `!= null`、`?.` 或显式 `typeof` 检查；只有自己代码里保证过类型的地方才配用 `!== null`。** 顶层字段（`ts` / `seq` / `session`）也一样，在 `buildSituation` 里统一收口。
- **⚠️ `tick()` 外面必须有一层 try/catch。** state 文件的形状取决于游戏版本、读档阶段、mod 版本 —— 我们没法假设它。一拍抛异常只该丢这一拍，不该升级成「扩展用不了」。错误照打日志（同一条 60 秒内只打一次），下一拍照常跑。
- **⚠️ 改导出时，替换锚点必须带整行。** 拿 `function xxx(` 当锚点、而原文是 `export function xxx(`，替换之后 `export` 会被留在新插的内容头上，`xxx` 静悄悄变成私有 —— **文件语法照样合法，没有任何报错**。真机表现不是「某个功能坏了」，是宿主 `导入失败`、**一条功能都用不了**。判据：锚点要包含行首修饰词（`export` / `async` / `default`），改完跑「`index.ts` 的 re-export 逐个存在」那条测试。这是「改稿副作用」在代码里的同一个形状：被点名的字改了，旁边的东西被带走。
- 数据目录是**所有 World 共用**的（`companion/data`），所以落盘的文件一律带 `pz-` 前缀。
- 词表（表情 / 动作）**现读**当前立绘包，不手抄 —— `whale` 有 30 个动作，`coo` 只有 18 个，写死任何一份换皮肤就失效。
- 判断「第一次读到数据」不能拿 `lastN === 0`，要一个独立的 `armed` 标志。一份从来没出过事的数据会让 `lastN` 一直是 0，于是第一次真出事就被当成「刚启动」吞掉。
- **状态类事件按档位去重，回落到正常时清记录。** 饿这件事会反复（吃到不饿、又饿了），那是两回都该说；但同一次饥饿从 82% 飘到 83% 不该再说一遍。记成布尔「说过了」就再也不会说了 —— 而这一局才刚开始。
- **`CharacterStat` 的新枚举一律走 `once()`。** `pcall` 接得住异常，接不住日志：Kahlua 每抛一次就打一整段堆栈，而 readPlayer 是每拍都跑的。缺的键只试一次，之后安静返回 nil。
- **容器身份不能把物品数量算进去。** 他拿走一件，`sig` 一变，外面就当成「换了个柜子」再报一遍——所以 `sig` 只用容器类型 + 所在格。
- **`getPlayerLoot()` 那个页面一直存在，没开容器时只是不可见。** 只判 `inventory ~= nil` 会在他走路时一直读到上次那个柜子，必须查 `isVisible()`。
- **⚠️ 「包了 pcall」不等于「包住了」。** 0.4.7→0.4.9 连栽三次，全是同一个形状：**抛出发生在表达式求值处，那时外面那层 pcall 还没建立。**
  - `statOnce(st, CS.PANIC, 'panic')` —— `CS.PANIC` 在**参数求值**阶段；访问一个这个构建没有的 Java 静态字段，Kahlua 当场抛。
  - `Perks and Perks[it.perk]` —— Java 类的字符串索引，同样裸奔。
  - `if next(sk) then` —— Kahlua 标准库不全，`next` 在某些构建里是 nil。
  - 三次本机都跑得通（42.21 恰好齐全），别人一装就整份 state 写不出来。**本机能跑不能证明别人能跑。**
  - 现在的做法：① 所有 `CharacterStat` 枚举在 `ensureEnums()` 里逐个 `pcall` 取一次缓存进 `ENUM`；② `readPlayer` **按段隔离**（`step(name, fn)`），某一段抛了只丢那一段，第一段失败打一次 `readPlayer step failed: <段名>` 进 console；③ 不用 `next()`，判空用计数器。
  - 判据：任何在**函数体之外**求值的东西（参数、索引、全局函数名），都得当成「可能抛且无人接住」。
- **⚠️ `CharacterStat` 的量纲不统一，不能拿一套 0..1 阈值套所有项。** hunger / thirst / fatigue / endurance 是 0..1，**pain / panic 是 0..100**。证据是游戏自己的调试菜单（`ISStatsAndBody.lua`：给 PAIN / PANIC 的滑条步长是 `1`，给 HUNGER 用默认 `0.01`）。真机上 `pain = 1.9` 被读成「190%」，还误判成 critical 说「疼到影响动作了」。**正确做法不是写死除以 100，而是读枚举自己的 `getMinimumValue()` / `getMaximumValue()`** —— 字段哪天换刻度都能跟上。
- **⚠️ 「有伤害值」不等于「是武器」。** 抹布的 `MaxDamage` 也是 1.5，日用品大多有这个字段。真机上因此对空手的人说「柜里那把伤害 1.5，拿了就能打」。判据要用游戏给的分类 `Category == "Weapon"`，不要用伤害。**同理：说「柜里那把」这种含糊指代，本身就是错位的温床 —— 要指名。**
- **定时扫描是最容易做成「不及时」的地方。** 容器原来固定每 3 拍扫一次（约 6 秒），而人翻一个柜台停留不了那么久。正解是拆成两半：**每拍只查身份**（两次 Java 取值，很便宜），**换了才扫内容**，再加一个低频兜底重扫跟内容变化。
- **`pz.need` / `pz.weapon` / `pz.loot` 的 key 必须带时刻。** 这两类同一档位可以再来一次，而 `pz.danger` 那种「一天一档只报一次」的 key 天然唯一；照抄它的写法，第二次会被宿主当成重复静默丢掉。
